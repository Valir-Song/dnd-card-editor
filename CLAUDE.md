# Памятка по D&D Card Editor

Общая рабочая памятка для Codex и Claude. Это проект Valir для своей игровой группы.
README описывает использование и формат данных, docs/ROADMAP.md — приоритеты и решения владельца.
Эта памятка описывает устройство кода, порядок работы и проверки. Поддерживать одну версию правил,
а не отдельные расходящиеся планы для разных помощников.

## Работа с владельцем

- Общаться по-русски, просто: сначала результат и значение для игрока, затем нужные подробности.
- Надёжность перед живой игрой важнее количества новых возможностей.
- Вести реализацию самостоятельно в пределах задачи. Решения о направлении и выпуске готовой версии — за владельцем.
- Разрешение влить изменения действует в рамках конкретной задачи. Не считать его бессрочным разрешением на будущие слияния.
- Не начинать пункты «Нужно решение владельца» и отложенные задачи без соответствующего ответа.
- Не публиковать личные макеты, картинки и секреты. В library/ добавлять только материалы, которые владелец разрешил распространять.
- В отчёте различать сделанное локально, отправленное в GitHub, влитое в main и опубликованное на сайте.
- Честно указывать непрошедшие и невыполненные проверки; чтение кода не доказывает отсутствие ошибок.

## Начало задачи и Git

1. Прочитать эту памятку, README и верх ROADMAP: «Ближайшие шаги», «Нужно решение владельца», «Известные проблемы».
2. Проверить git status, последние коммиты, свежесть origin/main и открытые PR. Сохранить чужие незавершённые изменения.
3. Использовать существующий checkout облачной задачи. Создавать worktree только по явной просьбе владельца.
4. Делать небольшую тематическую ветку от актуального main; не смешивать функцию, форматирование и постороннюю уборку.
5. Перед слиянием проверить итог с учётом свежего main. Не переписывать чужую историю и не использовать force push без отдельного основания.
6. Существующая удалённая ветка ещё не означает невыполненную задачу. Проверить её предков, PR и заменившие её решения.
   Старые экспериментальные ветки не вливать механически ради пустого списка: они могут вернуть удалённые механизмы.
7. Не удалять ветки и не закрывать спорные черновики без разрешения. Не подменять настоящее слияние фиктивным merge с отбрасыванием изменений.
8. Пользоваться уже предоставленной Git-аутентификацией. Отсутствие GH_TOKEN не доказывает отсутствие доступа.
   Работоспособность Git, GitHub API и push проверять отдельно. Не выводить значения переменных и файлы с учётными данными.
9. Никогда не выполнять reset --hard или checkout файла ради удобства проверки: можно потерять незакоммиченную работу.
   Для сравнения читать git show, а проверяемые копии держать вне рабочего дерева.

## Что должно оставаться верным

- Редактор собирается в один автономный HTML: без внешних шрифтов, скриптов, аккаунтов и обязательного сервера.
- Приложение на GitHub Pages — дополнительный способ запуска. Переносной HTML продолжает работать с диска офлайн.
- На сайте обычный документ — .dnd; локальный HTML по умолчанию сохраняется как HTML. JSON — дополнительный экспорт данных.
- «✓ В браузере» означает браузерную копию, а не запись документа на диск. В Firefox сохранение скачивает копию.
- Старые макеты читаются; новый смысл поля требует миграции. Новые необязательные поля не должны ломать старые данные.
- Импорт сначала проверяется. Повреждённые данные должны быть доступны для спасения, более новый неизвестный формат нельзя перезаписывать.
- Одно пользовательское действие — один понятный шаг отмены. Режим игры защищает оформление от случайной правки.
- Собственный слой жестов остаётся основой: Moveable и Selecto удалены, не возвращать их попутно.

## Данные, история и отрисовка

- Координаты и размеры в миллиметрах; лист 210×297. page — от 1 до MAX_PAGES; id уникален.
- Формат сейчас 3, источник истины — FORMAT_VERSION и MIGRATIONS в layout.js. Голый массив — формат 1.
  Миграции 1→2 исправляют старый кружочек, 2→3 превращают текстовые ресурсы в строки квадратиков.
- .dnd — обёртка JSON с items, formatVersion, id, именем и временем. id связывает файл с его браузерной копией.
- Невидимый character один на макет, не рисуется и не удаляется с листом; stats показывает его числа, не дублирует их.
- sheet задаёт фон и удерживает пустую страницу. Эти объекты исключены из обычного выделения и привязки.
- characterStats считает простые значения, fixed позволяет ручное исключение. Не превращать модуль в полный движок правил D&D.
- «Вписать в лист» не работает само: меняет число после известных подписей. Атаку оружия и хиты не затрагивает.
- store.change — обычная правка с перерисовкой; commit — завершение жеста; shown — правка уже видимого текста или узла.
  shown должен отметить актуальный снимок, чтобы следующая отрисовка не уничтожила редактор и курсор.
- replace используют восстановление и отмена без создания нового шага. Ошибка отрисовки не означает автоматический откат данных в памяти.
- История хранит снимки документа; крупные data: изображения — в общем пуле. Лимиты задаёт history.js.
  group/windowMs объединяют набор текста, ползунки и серию сдвигов. После перезагрузки история не сохраняется.
- Отрисовка сохраняет узлы неизменённых объектов, отдельно обновляет геометрию. Не заменять весь DOM на каждую клавишу.
- current() при выделенной группе может быть пустым. Для действий над группой брать getSelectionIds().
  При выделении текста карточки удаление не должно удалять родительскую карточку.

## Хранение и экспорт: важные границы

- IndexedDB хранит layouts и короткие meta без картинок. localStorage — запасной путь; при невозможности обоих — предупреждение.
- createSaver объединяет запросы во время записи в один следующий запрос самого свежего состояния; flush ждёт завершения.
- startup/freshness выбирают файл или браузерную копию по идентификатору и времени. Вытесненная копия сохраняется как :previous.
  Слишком новый формат получает отдельную рабочую идентичность, чтобы не затереть неподдерживаемую запись.
- Старое сохранение dnd-card-editor-v3 переносится, а повреждённый исходник предлагается скачать для восстановления.
- stable и beta используют разные браузерные хранилища и кэши. Файл с диска и сайт тоже нельзя считать одним местом хранения.
- save-file.js последовательно пишет через File System Access API. Ошибка или отмена не должны показывать успешную запись.
  Выбранный файл и реально завершённая запись — разные состояния; подпись времени относится к последней записи в этой сессии.
- Экспорт HTML строится из чистой исходной страницы, удаляет служебные узлы, выделение, сетку, масштаб и data-app-only.
  Не экспортировать живой DOM вместе с Tiptap и ручками.
- app/sw.js обновляет страницу через сеть с возвратом к кэшу. Скачанные справочник и готовые листы имеют отдельный кэш.
  Содержимое документов не отправляется на сервер.

## Команды и окружение

Репозиторий ориентирован на Node.js 22, Python 3.12 и Playwright из tests/requirements.txt.
Для воспроизводимости устанавливать зависимости по lock-файлу; после смены зависимостей/ветки обновлять установку.

```sh
npm ci --no-audit --no-fund
npm test
npm run typecheck
npm run build
npm run check:build
cmp dist/index.html DND_Card_Editor_standalone.html
npm run dev
python -m pip install -r tests/requirements.txt
python tests/run_e2e.py chromium
python tests/run_e2e.py firefox
CPU_THROTTLE=4 python tests/run_e2e.py chromium
```

- Для одного браузерного набора: EDITOR_BROWSER=chromium python tests/ci_run.py tiptap_browser_smoke.py.
- CPU_THROTTLE действует только в Chromium. Для повторения CI с замедлением нужны regression, canvas, nested и tiptap.
- .claude/hooks/session-start.sh относится к окружению Claude и не гарантирует подготовку Codex.
- Проверить действительные версии, пути и наличие браузеров. Не переносить предположения о предустановленном образе на другую машину.
- tests/browser_env.py допускает Chromium по /opt/pw-browsers/chromium, если ожидаемой сборки нет.
  При отсутствии подходящего браузера установить соответствующую закреплённому Playwright сборку в отдельный кэш, не заменяя системный браузер.
- В подготовленной среде Codex инструменты активируются через /workspace/.tools/dnd-env.sh, если файл существует.
  Он выбирает Node 22, npm 10, Python venv и отдельный PLAYWRIGHT_BROWSERS_PATH. Это локальная настройка, а не требование к чужому компьютеру.
- При ошибке npm ci проверить версию npm: в этой среде npm 10 работает с текущим lock-файлом, npm 11 отвергал отсутствующие записи необязательных платформ.
  Не исправлять это незаметной перегенерацией lock-файла во время установки.
- Не отключать TLS, проверки подписей/целостности и тесты ради зелёного результата. Сетевой запрет и отсутствие полномочий — разные причины.
- GitHub API использует api.github.com; загрузки Playwright могут требовать cdn.playwright.dev и playwright.download.prss.microsoft.com.
  Сохранённый черновик сетевых настроек ещё не означает, что они применились.

## Какие проверки нужны

- Чистая логика — соответствующие Node-тесты; интерфейс — существующие браузерные сценарии; смена вида — визуальное сравнение.
- Для существенного изменения редактора: Node-тесты, typecheck, сборка, автономность, совпадение standalone;
  наборы regression/canvas/nested/tiptap/visual/app в Chromium и Firefox, затронутые жесты также с CPU_THROTTLE=4.
- Для передачи проекта и разбора накопленных изменений выполнить полный доступный набор, а не только проверку синтаксиса.
- Документационная правка не требует новой формальной проверки, которая только повторяет текст.
- CI закрепляет ОС в workflow; не менять образ вслепую. Визуальный эталон CI — HEAD^1, локально по умолчанию origin/main.
  VISUAL_REFERENCE указывает HTML-файл, VISUAL_REF — Git-коммит. Не возвращать зависимость CI от движущегося main.
- tests/visual-accept.txt разрешает намеренную смену вида для версии. Не обновлять его, чтобы скрыть неожиданную разницу.
- tests/ci_run.py сохраняет код завершения и добавляет аннотации. Проверять завершение всех нужных наборов и фактические результаты.
- Настоящие диалоги выбора файла, повторное разрешение после перезапуска, печать на бумаге и удобство пальцем проверяет человек:
  поддельный File System Access API в тесте этого не доказывает. Список — tests/smoke.md.

## Ловушки браузерных тестов

- Сначала открыть нужную вкладку панели: скрытая кнопка не нажимается. Высота ленты не должна меняться от выделения.
- Ждать фокуса и состояния редактора, а не надеяться на фиксированную паузу; после жеста учитывать прокрутку.
- Перед закрытием страницы дождаться окончания фоновой записи: иначе запись прошлого шага может затереть подготовку следующего.
- Щелчок в углу карточки может попасть в ручку; для движения выбирать свободное поле. Тексты по умолчанию занимают ширину карточки.
- Alt до pointerdown включает выделение внутренних текстов; для отключения привязки при движении нажимать Alt после mouse.down().
- Привязку проверять в месте без случайных совпадений с краями и центрами других объектов или листа.
- Firefox под Playwright имеет ограничения мыши при эмуляции касаний и системного буфера. Отличать синтетическую проверку от настоящего действия.
- beforeunload под автоматизацией проверяется также событием и defaultPrevented, а не только наличием диалога.
- .el.image-el — изображение; img.card-bg-image — фон карточки. Путать их при поиске нельзя.
- Буфер событий слушается в capture, чтобы JSON объектов не попал в текст ProseMirror.
- Новые элементы должны быть учтены в правилах режима игры, нативных целей жестов, печати и чистого экспорта.

## Изменения, версии и выпуск

- Сохранять стиль изменяемого участка; не форматировать весь проект попутно. Длинные функции упрощать отдельной задачей.
- Логика без DOM — чистыми функциями; публичные интерфейсы — src/types/*.d.ts и JSDoc; strict не ослаблять.
- Комментарии к коду — коротко по-английски о причине; интерфейс, документация и PR — по-русски.
- Все четыре пакета Tiptap обновлять вместе, проверяя единственную копию ядра через npm ls @tiptap/core.
- Изменение редактора получает следующую beta по правилам README. Документационная передача проекта версию приложения не меняет.
- При смене версии согласованно обновлять package.json, package-lock.json, index.html, README и автономную сборку.
- После изменения src/, index.html или зависимостей выполнить npm run standalone; закоммиченный HTML обязан совпадать со сборкой.
  При конфликте генерируемого HTML разрешить исходники и пересобрать, не склеивать сборки вручную.
- main после успешных проверок публикуется на основной сайт через publish.yml при наличии PAGES_TOKEN.
  Слово beta в версии не означает изоляцию от основного сайта: отдельный канал /beta/ выбирается отдельно.
- scripts/site.mjs генерирует публичный README по структуре основного. Изменение заголовков проверить через tests/site.test.mjs.
- Лицензия кода — AGPL-3.0-only, справочника SRD — CC-BY 4.0; сохранять NOTICE и атрибуцию.
