Этот файл читается автоматически в начале каждой сессии Claude Code. Здесь собрано то,

## Порядок работы (сложился и одобрен)
1. Ветка от свежего `main`: `feature/…`, `fix/…`, `docs/…`, `chore/…`.
2. Правки → `npm test`, `npm run typecheck`, `npm run standalone`, браузерные наборы
   (обычный прогон, `CPU_THROTTLE=4` и Firefox, если хук его поставил).
3. Коммит, push, PR через `gh api` (REST). Тело PR — по-русски: «что и зачем», «Проверка».
4. Подписка на активность PR и страховочная проверка (send_later ~50 мин); удалить её, когда
   CI закончился или PR влит.
5. **Вливать только по явному слову владельца** («вливай», «да, вливай оба»). Метод — `merge`.
   Без просьбы — не вливать (однажды автоматический классификатор такую попытку отклонил).
6. После вливания: `git checkout main && git reset --hard origin/main && npm ci`,
   быстрая проверка (`npm test`, сборка совпадает со standalone).
- Цепочка PR: второй PR открывать с `base` = ветка первого; после вливания первого
  перенацелить второй на `main` (`gh api -X PATCH …/pulls/N -f base=main`) и только потом вливать.
- Номер версии меняется в каждом PR с изменением поведения или кода редактора (см. «Версия»).

## Устройство проекта
Офлайн-редактор листов A4 для D&D 5e (бард Ричард Сэдсонг). Весь редактор — **один HTML-файл**
без сервера и интернета: Vite + `vite-plugin-singlefile` встраивают JS, CSS и стартовый макет.
Это главное достоинство проекта; не добавлять ничего, что требует сети или второго файла.

### Данные
- Макет — JSON-массив объектов. Поля: `id`, `kind` (`header|note|resources|section|card|shape|image|textbox`),
  `page` (1–2), `x,y,w,h` **в миллиметрах** (лист 210×297), `z`. Полный список — `src/types/layout.d.ts`.
- Текст: `title/subtitle/meta/detail/text` (простой) и `…Html` (оформленный, Tiptap). Смещения текстов
  карточки — `textFrames[поле] = {x,y,w,h}` относительно карточки. Значок — `level`, `badgeX/badgeY`.
- Картинки — `data:` URL прямо в объекте (`src` у `image`, `bgImage` у `card`).
- Формат совместим с 3.2: старые макеты импортируются как есть. **Ломать совместимость нельзя**;
  если нужно новое поле — делать его необязательным со значением по умолчанию.
- `normalizeLayout` отвергает неизвестный `kind`, страницу вне 1..`PAGE_COUNT` (=2), нечисловую
  геометрию; чинит пропущенные `id/page/z` и дубликаты `id`.

### Хранение (с 3.9 — `src/editor/storage.js`)
- **IndexedDB** `dnd-card-editor`: хранилища `layouts` (запись `{id,name,savedAt,items}`) и `meta`
  (`{id,name,savedAt,count,bytes}` — список без картинок). Если базу открыть нельзя (или `?storage=local`
  в адресе — так тесты проверяют запасной путь) — **localStorage**: `dnd-card-editor-layout:<id>` и индекс
  `dnd-card-editor-layouts`; если и он недоступен — `none` (предупреждение «скачивайте HTML»).
  Какое хранилище выбрано — `html[data-storage]`.
- **Одна запись на макет** (с 3.9.0-beta.2), номер — `html[data-layout-id]`. Какой открыть, решает
  `chooseLayout` (freshness.js, Node-тесты): файл с `#initial[data-layout-id]` (экспорт 3.9+) → своя запись;
  файл с одним `data-saved-at` (экспорт 3.3–3.8) → `f-<hash(содержимое+время)>`, стабильно при каждом
  открытии, и подсказка `newer`, если позже сохранена другая работа; чистый файл (релиз/шаблон) →
  последняя по `savedAt` запись (иначе новый `m-…`). Затем, как раньше, свежее из «файл/своя запись».
- Записи с `:` в номере — копии (`<id>:previous` — вытесненная при открытии более нового файла);
  они не «последний макет» и не открываются из «Мои макеты» (только JSON и удаление).
- Экспорт пишет `data-layout-id`, `data-layout-name`, `data-saved-at`; имя файла — `fileBase(название)`.
- «Мои макеты» (`layouts-dialog.js`): открыть другой = как открыть другой файл (`history.reset`, своя
  история); «Сбросить» в чистом файле начинает новый макет, в файле с номером — перезаписывает свой.
- Старое сохранение 3.2–3.8 переносится в запись `default` один раз (пометка `dnd-card-editor-v3-moved`),
  если записи `default` ещё нет (её мог создать 3.9.0-beta.1).
- Запись фоновая (`createSaver`): запросы во время записи схлопываются в одну запись новейшего
  состояния; `backend.put` обязан скопировать запись **синхронно** (IndexedDB `put` и `JSON.stringify`
  так и делают). Состояние — `html[data-save-state]` = `saved|saving|error` и значок `#saveState`.
  `beforeunload` спрашивает «покинуть?», пока состояние не `saved`. «Сохранить» ждёт `flush()`.
- Старое сохранение 3.2–3.8: localStorage `dnd-card-editor-v3` (+`-meta`) **никогда не удаляется**. `-recovery` — копия
  повреждённого (в localStorage, если помещается). `dnd-card-editor-snap` — настройки привязки.
- В тестах сохранённое читать только через `saved_record/saved_layout/put_saved/remove_saved`
  из `tests/browser_env.py` (они ждут конца фоновой записи); перед `page.close()` после правки —
  дождаться `saveState!=='saving'`, иначе запись не успеет.
- **Chrome хранит localStorage и IndexedDB всех локальных HTML-файлов в одном месте** (проверено:
  запись из одного файла видна другому) → поэтому у каждого макета свой номер записи. Firefox тоже
  даёт файлу с диска IndexedDB (видно в CI: `::notice` «storage for local files is …»).
- Свежесть внутри одного макета: скачанный HTML несёт `data-saved-at`, запись — `savedAt`; открывается
  более свежее, второе доступно из предупреждения. У чистого файла `data-saved-at` нет → побеждает запись.
- IndexedDB вмещает сотни МБ; localStorage ~5 МБ. При ошибке записи — предупреждение и «⚠ Не сохранено».
  Надёжное хранение — по-прежнему «Скачать HTML».
- `editor.js` начинается с `await` (открыть хранилище, `loadStartupLayout` из startup.js): модуль с top-level await,
  сборка Vite это поддерживает.

### Store («секретарь»)
- `store.change(mutate, {group, windowMs})` — правка данных → перерисовка → шаг отмены → сохранение.
  `mutate` правит на месте или возвращает новый массив.
- `store.commit()` — данные уже изменены (жест закончен): перерисовка → шаг → сохранение.
- `store.shown(item, …)` — правка **уже на экране** (набор в Tiptap, текст значка, ползунки картинки,
  цвет фона): отметить отрисованным, без перерисовки, шаг → сохранение.
- Если перерисовка бросила исключение — ни шага, ни сохранения (на этом стоит защита импорта).
- `store.replace` + `store.render` — без шага (откат импорта, восстановление при отмене).
- Тест в `source.test.mjs` запрещает модулям (кроме `store`, `history`, `render`) вызывать
  `persist/draw/setItems/markRendered/saveToStorage` и `history.commit` напрямую. Новые модули получают `store` через параметры и описывают их
  JSDoc-типом `import('../types/layout').Deps`.

### Отрисовка (инкрементальная, `render.js`)
- `rendered: Map(id → {node, snap})`, `snap = JSON.stringify(item)`.
- При `draw()`: снимок совпал → узел остаётся (Tiptap переподключается `rich.rebind`); изменилась только
  геометрия (`GEOMETRY = x,y,w,h,z,textFrames,badgeX,badgeY,badgeCustomPosition`) → `patchGeometry`;
  иначе — узел и его редакторы пересоздаются на том же месте. Порядок узлов в DOM = порядок данных.
- **Любое не-геометрическое поле, изменённое без `store.shown`, пересоздаёт элемент и уничтожает его
  редакторы Tiptap** (теряется фокус/курсор). Правка, которая сама обновила DOM, — через `store.shown`.
- Новое поле, которое меняется жестом и патчится на месте, добавлять и в `GEOMETRY`, и в `patchGeometry`.
- `draw()` в конце зовёт `afterDraw` из editor.js: `canvas.afterDraw()`, `innerCanvas.afterDraw()`, `syncTextBoxTools()`.

### Закрепление (`locked`, с 3.11)
- Закреплённый объект: `begin()` его пропускает (группа двигает остальных), ручек нет (`.has-locked`), у рамки замок
  `.gesture-lock`; при всех закреплённых полосы за краем выключены (`.locked`). Нажатие на него (не на текст,
  не на `.level`/`⠿`) запускает рамку-выделение, щелчок без движения выделяет его. Рамка-выделение закреплённые
  не берёт. Текстовые рамки закреплённой карточки и её значок не двигаются; текст, цвет, слои — меняются.
- Каждой новой функции, которая двигает или удаляет объекты (стрелки, выравнивание), — пропускать закреплённые.
  Выравнивание учитывает закреплённый как опору (входит в рамку выделения), но не двигает; распределение его
  не считает.

### Слой жестов
- События указателя в фазе захвата на `.page`; поверх каждой страницы `.gesture-layer` внутри `.stage`,
  позиционируется в мм. Рамка `.gesture-frame`, ручки `.gesture-handle[data-dir]`, полосы `.gesture-edge`
  за краем рамки, рамка-выделение `.gesture-marquee`.
- `follow()` следит за одним указателем и для мыши дублирует `mousemove/mouseup` (Firefox с Shift
  может проглотить `pointerup`). Перетаскивание невыделенного объекта — синхронно, одним движением.
- Масштаб пикселей в мм: `210 / page.getBoundingClientRect().width`.
- Привязка: края/центры объектов той же страницы, рамка листа 5 мм, центр листа; порог 6 px экрана;
  Alt отключает; сетка 1/2,5/5 мм. Включённая сетка рисуется `.stage[data-grid] .page::before` (под объектами,
  не печатается); `cleanExport` снимает `data-grid` — иначе файл, открытый с включённой сеткой, унёс бы его в экспорт.
- Равные промежутки (3.11): `snapMove(..., {others})` сравнивает привязку к линии и `gapSnap` (ряд/столбец —
  объекты, перекрывающие перетаскиваемый поперёк оси; промежуток меряется до ближайшего, кто заканчивается раньше,
  поэтому подложки и рамки не ломают ряд); ближе — то и берётся, при равенстве линия, но отметки `.gap-guide`
  показываются. Тексты карточки (`inner-canvas`) прилипают только к `boxLines([карточка, её поле, другие тексты])`,
  без сетки и без объектов листа; направляющая `.snap-guide.inner-guide` — в пределах карточки.
- `canvas.nudge` / `innerCanvas.nudge` — сдвиг выделения (стрелки); `clampMove` держит группу на листе;
  шаг отмены склеивается группой `nudge:<ids>` (окно 1 с).

### История
- Снимок = строка JSON всего макета; лимит 60 шагов и 48 МБ. Строки `data:` длиной ≥1024 хранятся
  в пуле один раз, в снимке — ссылка `\u0000image:N`; пул чистится от неиспользуемых.
- `group` + `windowMs` склеивают серию правок (набор текста 650 мс, ползунки 1200 мс) в один шаг.

Браузерные наборы: `regression` (20 разделов, 17–20 — закрепление, стрелки и сетка, выравнивание, умная привязка; разделы про хранение — для обоих хранилищ: импорт, повреждённое сохранение, перенос 3.8, 7 МБ, ошибка записи, экспорт, печать,
ручки при прокрутке, свежесть, перетаскивание одним движением, привязка, слой жестов и касания,

`tiptap` (текст и форматирование).
`visual` — снимки обеих страниц (шаблон и лист со всеми видами объектов) **против редактора из `main`**,
отрисованного на той же машине (git show origin/main:DND_Card_Editor_standalone.html; `VISUAL_REFERENCE=`
— другой эталон). Порог 0,05 % пикселей; при разнице картинки new/reference/diff — в `tests/visual-out/`.
Намеренно меняешь вид — впиши новую версию в `tests/visual-accept.txt` (иначе CI красный). Эталонных

## Версия и сборка
- При смене версии править: `package.json`, `package-lock.json` (строки 3 и 9), `index.html`
  (`<meta … name="editor-version">`, `<title>… — X.Y Beta</title>`, надпись «редактор X.Y beta»
  на панели), `README.md` («Текущая версия» и «История версий»). Затем `npm run standalone`.
- `DND_Card_Editor_standalone.html` закоммичен и **должен совпадать байт в байт со сборкой**
  (CI сравнивает `cmp`; `source.test.mjs` проверяет версию). После любой правки `src/`, `index.html`
  или зависимостей — `npm run standalone` и коммит файла.
- Конфликт в standalone при слиянии веток: взять любую сторону и пересобрать `npm run standalone`.
- Tiptap: все четыре пакета закреплены точной версией (сейчас 3.32.0) — иначе в сборку попадают две
  копии ядра. При обновлении менять все четыре вместе и проверять `npm ls @tiptap/core` (одна копия).

## Окружение облачной сессии (ловушки)
- Каждая сессия начинается на чистом компьютере; хук `.claude/hooks/session-start.sh` ставит
  зависимости. **Хук срабатывает только при старте**: после `git checkout` другой ветки делать `npm ci`
  самому (разные ветки — разные зависимости; странные ошибки сборки обычно отсюда).
- Python Playwright закреплён на 1.56.0 под предустановленный Chromium (`/opt/pw-browsers`).
  **Chromium никогда не переустанавливать** (`playwright install` без имени браузера или с `chromium`).
  Firefox ставит хук: `python3 -m playwright install firefox` (с 23.10.2026 владелец открыл в окружении
  `cdn.playwright.dev` и `playwright.azureedge.net`). Хук пишет «Firefox for browser tests: ready» или
  «not available» — во втором случае Firefox проверяется только в CI. Все наборы в Firefox:
  `python3 tests/run_e2e.py firefox` (~3 мин); `CPU_THROTTLE` в Firefox не действует.
- Клон неполный: для новой ветки добавлять refspec, иначе ветка «не видна» и хук git-проверки ругается:
  `git config --add remote.origin.fetch '+refs/heads/<ветка>:refs/remotes/origin/<ветка>'`.
- GitHub: только REST через `gh api` (GraphQL закрыт). Логи заданий CI закрыты прокси — причину падения
  смотреть в аннотациях check-run (их пишет `tests/ci_run.py`: хвост вывода упавшего набора):
  `gh api repos/Valir-Song/dnd-card-editor/commits/<sha>/check-runs`, затем `…/check-runs/<id>/annotations`.
- CI (`.github/workflows/verify.yml`) идёт ~4–6 мин: Node-тесты, typecheck, сборка, сверка standalone,
  4 набора × Chromium/Firefox, затем 4 набора в Chromium с `CPU_THROTTLE=4`.
- Атрибуция коммитов и PR — по системному напоминанию сессии. Идентификатор модели в коммиты,
  PR и файлы репозитория не писать.

## Уроки (на чём уже обжигался)
- **Не откатывать незакоммиченный файл через `git checkout <файл>`** ради проверки «падает ли тест на
  старом коде» — так однажды стёрлись свежие правки. Сначала копия в scratchpad, потом
  `git show HEAD:<файл> > <файл>`, потом вернуть копию.
- Регрессионный тест считается настоящим, только если он **падает на старом коде** — проверять это.
- Массовые замены `sed` по коду проверять глазами: замена Selecto→marquee однажды превратила
  `querySelectorAll` в `querymarqueerAll`. Теперь такое ловит typecheck.
- Кнопки панели лежат во вкладках: в тестах сначала открыть вкладку (`[data-tab="figures"]`),
  иначе клик по скрытой кнопке зависает на 30 с. Набор `tiptap` проверяет число вкладок (сейчас 7):
  новая вкладка — поправить и его.
- Щелчок в тесте по уже выделенной карточке в точке (3,3) попадает в ручку-уголок, а у самого текста ставит
  курсор в текст. Без текста и ручек — левое поле карточки: `position={'x':4,'y':20}`. Тексты карточки по
  умолчанию во всю ширину: «по правому краю» их не меняет, проверять сдвинутые (`textFrames`).
- Класс элемента картинки — `.el.image-el` (не `.el.image`); фон карточки — `img.card-bg-image`.
- Firefox под Playwright: эмуляция касаний (`has_touch`) ломает мышь — касания проверять отдельным
  контекстом и только в Chromium; Shift+рамка на пустом листе в Firefox под Playwright не получает
  событий — в тесте синтетические PointerEvent, вживую проверяет владелец (`tests/smoke.md`).
- Гонки на медленных машинах: ждать появления ручек (`wait_for_function`) и двух кадров
  `requestAnimationFrame`, а не фиксированные паузы; прогон `CPU_THROTTLE=4` ловит такое до CI.
- Фоновая запись переживает закрытие вкладки и может «приземлиться» позже следующего шага теста: в CI
  это однажды перезаписало подготовленное сохранение. Поэтому `open_editor` в regression ждёт
  `saveState!=='saving'` перед `page.close()`; в новых тестах делать так же.
- `beforeunload`-диалог Chrome под Playwright не показывает: проверять сам обработчик
  (отправить событие и смотреть `defaultPrevented`).
- `ci_run.py` превращает строки `NOTE …` в `::notice` — так видно факты из успешного прогона.
- Тест привязки доказывает что-то, только если в точке назначения нет **случайной** линии другого объекта
  (края, центра, линий листа 0/5/105/205/210): в разделе 20 три раза находились такие совпадения, и старый код
  «проходил». Проверять `collectLines` в Node и прогонять тест на старой сборке.
- Alt, зажатый **до** нажатия на карточку, — рамка выделения текстов внутри неё; для «перетаскивания без
  привязки» в тестах Alt нажимать после `mouse.down()`.
- Набор `regression` после клика по тексту должен ждать фокуса (`into_text` в разделе 18): в CI Firefox клавиши
  иногда приходили раньше курсора.
- После жеста страница могла прокрутиться: сравнивать `style.left/top` узла, а не координаты окна.
- Moveable/Selecto удалены (3.5) — не возвращать; свой слой жестов проще и надёжнее.
- В JS-файлах TypeScript считает объекты «открытыми» и не ругается на незнакомые свойства —
  поэтому API (Store и т. п.) описаны интерфейсами в `src/types/*.d.ts`, а не выводятся из кода.
- С группой (рамка или Shift+клик) `current()` = `null`: кнопки, действующие на выделение, брать
  `getSelectionIds()` (а при выделенном тексте карточки — `current()`), иначе они молча ничего не делают.
- Реальный Ctrl+V в Tiptap под Playwright иногда читает буфер раньше, чем легла прошлая запись
  (и без наших правок) — вставку в текстовое поле в тестах отправлять событием прямо в поле. Firefox под
  Playwright буфер не даёт: раздел 16 там шлёт ClipboardEvent, а DataTransfer крепит через
  `Object.defineProperty(event,'clipboardData',…)` — из конструктора Firefox его выбрасывает; `SYNTHETIC_CLIPBOARD=1`
  запускает эту ветку в Chromium.
- События буфера (copy/cut/paste) браузер шлёт туда, где последний раз было выделение текста, даже если
  фокус уже на листе: ProseMirror вставлял туда JSON объектов и вырезал свой текст. Поэтому clipboard.js
  слушает в фазе захвата и, забирая событие, вызывает `stopImmediatePropagation`.
- Строгие модули (`tsconfig.strict.json`): параметры описывать JSDoc (`@param`), пустые массивы и
  `Map`/`Set` — через `/** @type */`; `null` проверять явно, а не `?.` с последующим обращением.
  Строгий режим уже нашёл: `canvas.getContext('2d')` может вернуть `null` (теперь картинка остаётся
  несжатой, а не падает); перетаскивание значка карточки, которой уже нет (3.11.0 beta.6).

## Стиль кода
- Подражать окружающему коду. Старые модули (`editor.js`, `render.js`, `objects.js`, `files.js`, `layers.js` …) —
  плотные однострочники; новые (`canvas-controls`, `inner-canvas`, `geometry`, `snapping`, `store`,
  `images`) — обычное форматирование с пробелами. Не переформатировать чужое попутно.
- Комментарии в коде — по-английски, коротко «зачем». Надписи интерфейса, README, PR — по-русски.
- Геометрия и логика без DOM — чистыми функциями в отдельном модуле с Node-тестами.
- Каждая новая функция: Node-тест для логики + раздел браузерного теста для поведения + строка
  в `tests/smoke.md`, если нужна ручная проверка.
