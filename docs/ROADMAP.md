# Дорожная карта D&D Card Editor

Живой план проекта. Порядок — по важности: сначала то, что защищает работу владельца и ускоряет
дальнейшую разработку, потом удобства, потом крупные новые возможности. У каждого пункта —
**зачем** (какую боль снимает), **что** (как примерно сделать) и **размер**:
S — до пары часов, M — день, L — несколько дней, XL — неделя и больше.

Отмечай сделанное и переноси в раздел «Сделано» со ссылкой на PR.

---

## Принципы (не меняются от пункта к пункту)
1. **Один HTML-файл, без интернета и установки.** Любая функция должна работать в скачанном файле
   офлайн в Chrome и Firefox. Никаких серверов, аккаунтов и внешних шрифтов/скриптов.
2. **Работа владельца не теряется.** Старые макеты (с 3.2) открываются; формат меняется только
   добавлением необязательных полей; при любой ошибке — понятное сообщение и путь назад (Ctrl+Z, копия).
3. **Перед игрой надёжность важнее новизны.** Крупные переделки — не накануне сессии D&D.
4. **Каждая функция — с тестом**, который падает без неё; CI в Chromium и Firefox зелёный.
5. **Маленькие PR.** Один шаг — один PR, его можно проверить и откатить отдельно.

## Уровень 1 — техническая основа (ускоряет всё остальное)

### 1.1 Строже проверка типов, по шагам — S/M (шаг 1 сделан, #19)
- **Зачем:** сейчас TypeScript ловит опечатки в именах, но молча пропускает многое: забытые
  аргументы, `undefined` вместо числа, неверные возвраты. Чем строже проверка, тем раньше
  ошибка видна — до тестов и задолго до игры.
- **Что:** включать `strict` (или `noImplicitAny` + `strictNullChecks`) по модулям: сначала
  чистые (`geometry`, `snapping`, `store`, `history`, `images`, `layout`, `freshness`), потом
  жесты, потом `editor.js`. Через `// @ts-check` в файле или отдельный tsconfig для «строгих» модулей.
- **Сделано:** `tsconfig.strict.json` (`strict: true`) для `store`, `history`, `images`, `geometry`,
  `snapping`, `layout`, `freshness`; `npm run typecheck` проверяет оба конфига. Типы геометрии —
  `src/types/geometry.d.ts`.
- **Дальше:** `notice`, `toolbar-tabs`, `dom`, затем `inner-canvas` и `canvas-controls` (нужны типы
  записей жеста), `rich-text` (типы Tiptap уже есть), в конце `editor.js` и модули панели.

### 1.2 Номер версии формата макета — S
- **Зачем:** впереди функции, которые добавят новые поля (больше страниц, поворот, роли). Явный
  `formatVersion` в экспорте позволит безопасно «переселять» старые макеты и понимать, из какой версии
  пришёл файл, когда владелец пришлёт его на починку.
- **Что:** обёртка `{formatVersion, items}` в JSON-экспорте **с сохранением** приёма голого массива;
  миграции по версиям в `layout.js` с Node-тестами на каждую.

### 1.3 Разобрать `editor.js` — M
- **Зачем:** это самый плотный файл (≈270 строк однострочников): загрузка, сохранение, отрисовка,
  связывание модулей. Его тяжело читать и рискованно менять, а почти каждая новая функция его трогает.
- **Что:** вынести отрисовку (`buildElement`, `patchGeometry`, `draw`, `rendered`) в `render.js`,
  хранение (`saveToStorage`, ключи, freshness на старте) — в `storage.js`. Поведение не меняется,
  все браузерные наборы — страховка. Делать отдельным PR без новых функций.

### 1.4 Снимки экрана в тестах (визуальная регрессия) — M
- **Зачем:** тесты проверяют поведение, но не «как выглядит». Сдвинутый на 2 мм текст или пропавший
  фон сейчас заметит только владелец — уже на распечатке.
- **Что:** Playwright-скриншоты стартового макета и пары типовых карточек; сравнение с эталоном
  с допуском; эталоны обновляются осознанно.

### 1.5 Хранилище побольше: IndexedDB вместо localStorage — M (сделано, 3.9.0 beta.1)
- **Зачем:** localStorage — ~5 МБ на все локальные файлы Chrome. Даже со сжатием два-три макета
  с фото упрутся в лимит, и автосохранение молча откажет (предупреждение есть, но работа не сохраняется).
  IndexedDB даёт сотни МБ. **Делать вместе с 2.1** — оба меняют одно и то же место.
- **Что:** асинхронное сохранение в IndexedDB, localStorage — запасной вариант; перенос существующего
  сохранения при первом запуске; тесты на квоту и повреждение переписать.
- **Сделано:** `storage.js`, значок состояния, вопрос при закрытии с несохранёнными изменениями;
  тесты проверяют оба хранилища; макет 7 МБ сохраняется (на 3.8 — нет).

### 1.6 Проверка в Firefox до CI — S (если окружение позволит)
- **Зачем:** Firefox сейчас проверяется только в CI, ошибки «только в Firefox» видны с опозданием.
- **Что:** выяснить, можно ли поставить Firefox под Playwright 1.56 в облачном окружении (настройка
  окружения/скрипт подготовки), не ломая предустановленный Chromium.

## Уровень 2 — защита данных

### 2.1 Отдельное сохранение для каждого макета — M (сделано, 3.9.0 beta.2)
- **Зачем:** Chrome хранит сохранения всех локальных HTML-файлов в одном месте. Два файла с разными
  персонажами перезаписывают одно сохранение. Плашка «открыть другой макет» спасает, но это последний
  известный способ потерять работу.
- **Что:** у каждого макета свой идентификатор (`layoutId`, записывается в `#initial` при экспорте
  и в сохранение); ключ хранения — по нему. Список сохранённых макетов с датами и кнопкой «открыть» /
  «удалить». Старое общее сохранение — перенести как «макет без имени». Название макета
  (например, «Ричард Сэдсонг») — в заголовке вкладки и имени скачиваемого файла.
- **Сделано:** номер макета в файле, старые файлы — номер по содержимому, чистый файл — последний
  макет; «Мои макеты»; название. Тест: на 3.9.0 beta.1 файл B показывал работу файла A, теперь своё.

### 2.2 Напоминание скачать HTML — S
- **Зачем:** надёжное хранение — это скачанный файл, а браузер может очистить сохранение
  (очистка истории, режим инкогнито, переполнение).
- **Что:** ненавязчивая плашка «изменения не скачаны уже N минут / с прошлой игры»; время последнего
  скачивания хранить рядом с сохранением.

### 2.3 Сохранение прямо в файл (File System Access API, только Chrome) — M
- **Зачем:** «Скачать HTML» каждый раз создаёт новый файл в «Загрузках» (файл (1), (2)…). В Chrome
  можно один раз выбрать файл и дальше сохранять в него по Ctrl+S — как в обычной программе.
- **Что:** кнопка «Сохранить как файл…» → дальше Ctrl+S пишет в тот же файл. В Firefox API нет —
  там остаётся скачивание. Аккуратно с правами доступа и ошибками записи.

### 2.4 Отмена переживает перезагрузку — M
- **Зачем:** сейчас история Ctrl+Z пропадает при закрытии вкладки.
- **Что:** сохранять последние шаги истории (с пулом картинок) в IndexedDB; ограничить объём.
  Зависит от 1.5.

## Уровень 3 — удобство каждый день

### 3.1 Новые объекты в свободном месте — S
- **Зачем:** все фигуры, картинки и текстовые поля появляются в одной точке (35×110 мм) и
  перекрывают то, что под ними.
- **Что:** ставить рядом с выделенным объектом или в видимую часть активной страницы; сдвигать,
  пока не найдётся свободное место; не вылезать за лист.

### 3.2 Действия с группой: дублировать, слои, фон, удалить — M
- **Зачем:** выделить несколько объектов уже можно, а сделать с ними почти ничего нельзя.
  Фундамент для 3.3.
- **Что:** «Дублировать» копирует всю группу со сдвигом; слои двигают группу, сохраняя порядок внутри;
  цвет фона применяется ко всем; всё — одним шагом отмены.

### 3.3 Выравнивание и распределение — M (после 3.2)
- **Зачем:** ровные столбцы карточек одной кнопкой вместо подгонки по миллиметру.
- **Что:** выровнять по левому/правому/верхнему/нижнему краю и центрам; распределить с равными
  промежутками; «сделать одинаковой ширины/высоты». Чистые функции в `geometry.js` + Node-тесты.

### 3.4 Сдвиг стрелками — S
- **Зачем:** точная подгонка мышью утомляет. Стрелки — на 1 мм, Shift+стрелки — на 5 мм (или шаг сетки).
- **Что:** обработчик клавиш вне текстового поля; серия нажатий — один шаг отмены (`group`).

### 3.5 Копировать/вставить объекты (Ctrl+C / Ctrl+V) — S/M
- **Зачем:** привычный способ дублировать и переносить карточки между страницами и даже между
  файлами (через буфер обмена как JSON).
- **Что:** не конфликтовать с Ctrl+V картинок и с вставкой текста в Tiptap.

### 3.6 Привязка текстовых рамок и одинаковые промежутки — M
- **Зачем:** привязка работает для объектов листа, но не для текстов внутри карточки; подсветка
  равных промежутков помогает выстраивать сетку карточек.
- **Что:** переиспользовать `snapping.js` в `inner-canvas.js`; в `snapMove` — поиск равных зазоров
  с соседями и их подсветка.

### 3.7 Блокировка объекта — S
- **Зачем:** фоновые рамки, заголовки секций и декоративные фигуры постоянно случайно сдвигаются
  при выделении карточек рамкой.
- **Что:** поле `locked`; заблокированный объект не тянется и не попадает в рамку-выделение,
  но редактируется текст. Значок замка у выделения.

### 3.8 Поиск по макету — S
- **Зачем:** на двух плотных страницах трудно найти нужное заклинание.
- **Что:** поле поиска; подсветка и выделение найденных карточек, переход к ним.

### 3.9 Поведение текста при растягивании карточки — S/M (отложено владельцем)
- **Зачем:** сейчас тексты прижаты к левому верхнему углу и не следуют за правым/нижним краем.
- **Что:** обсудить с владельцем желаемое поведение (якоря, пропорциональное смещение) перед работой.

## Уровень 4 — больше возможностей макета

### 4.1 Масштаб холста — M
- **Зачем:** на ноутбуке лист мелкий, мелкий текст правится вслепую; на большом мониторе — наоборот.
- **Что:** масштаб 50–200 %, Ctrl+колесо, «по ширине». Жесты уже считают мм через фактическую ширину
  страницы — проверить привязку, ручки и рамку-выделение при масштабе. Не одновременно с 4.2.

### 4.2 Больше двух страниц — M/L
- **Зачем:** заклинаний и способностей растёт с уровнем; двух листов скоро не хватит.
- **Что:** список страниц (добавить/удалить/переставить), `PAGE_COUNT` → данные; перенос объекта
  на другую страницу; печать всех страниц. Нужен 1.2 (версия формата).

### 4.3 Стили и темы — M
- **Зачем:** цвета и шрифты сейчас задаются у каждой карточки отдельно; перекрасить весь лист под
  другого персонажа — долго.
- **Что:** набор «тем» (палитра, шрифты, вид значков) и стили по типу карточки (заговор, 1-й круг …).

### 4.4 Поворот объектов — L (строго последним в этом уровне)
- **Зачем:** диагональные ленты, повёрнутые картинки, декоративные элементы.
- **Что:** поле `rotation` у объекта; ручка поворота; привязка, рамка-выделение, выравнивание и ручки
  должны учитывать поворот. Затрагивает всю геометрию — поэтому после всех пунктов 3.x и 4.1–4.2.

## Уровень 5 — D&D-возможности (куда расти дальше)

Это направления, которые превращают «редактор листа» в «инструмент игрока». Порядок внутри —
от самого полезного за столом.

### 5.1 Режим игры: отмечать ресурсы прямо на экране — M/L
- **Зачем:** во время игры лист открыт на ноутбуке или планшете, но отмечать потраченные ячейки,
  вдохновение и HP приходится карандашом на бумаге.
- **Что:** переключатель «Игра»: тексты не редактируются, а □ в «Ресурсах» становятся кнопками
  ☐/☑, счётчики (HP, ячейки по кругам, вдохновение) — с кнопками ±. Кнопка «Длинный отдых» сбрасывает
  всё. Крупные цели для пальца на планшете (слой жестов уже понимает касания).
- **Почему важно:** это то, ради чего лист открывают каждую сессию.

### 5.2 Карточки из данных: роли и импорт списка заклинаний — M/L
- **Зачем:** карточки набираются вручную; у карточек есть роли (social/control/damage/support),
  но они нигде не видны.
- **Что:** показ ролей цветной меткой (включаемо); импорт списка заклинаний из CSV/JSON
  (название, круг, школа, время, дистанция, длительность, концентрация, описание) с раскладкой
  карточек по сетке. Готовый справочник — только из открытых источников (SRD 5.1, лицензия CC-BY 4.0,
  с указанием источника); тексты из платных книг не встраивать.

### 5.3 Шаблоны персонажей — M
- **Зачем:** редактор сделан под барда Ричарда, но тот же лист нужен для других персонажей и игроков.
- **Что:** «Новый лист» из шаблона (пустой, бард, заклинатель, воин); шапка с параметрами как
  отдельный объект с полями (КД, HP, СЛ, атака, скорость), а не просто текст.

### 5.4 Печать карточек отдельно (формат игральных карт) — M
- **Зачем:** часто удобнее держать заклинания стопкой карт 63×88 мм, а не листом.
- **Что:** режим печати «карты»: каждая карточка — на своей карте, раскладка 3×3 на A4 с метками реза.

### 5.5 Чёрно-белая печать и экономия чернил — S
- **Зачем:** цветные фоны и картинки съедают картридж; часть игроков печатает на ч/б принтере.
- **Что:** переключатель в печати: убрать фоны-картинки, заливки — светло-серым, текст — чёрным.

### 5.6 Экспорт карточки картинкой — S/M
- **Зачем:** поделиться заклинанием в чате группы (Discord/Telegram) или вставить в заметки мастера.
- **Что:** «Скачать PNG» для выделенных объектов (рисование узла на canvas без внешних библиотек
  или с крошечной встраиваемой).

### 5.7 Уровни персонажа и подготовленные заклинания — L
- **Зачем:** при повышении уровня меняется набор заклинаний и число ячеек; часть заклинаний
  подготовлена, часть нет.
- **Что:** метка «подготовлено» на карточке и фильтр видимости; ячейки по уровню из таблицы класса.
  Требует 5.2/5.3.

## Уровень 6 — может пригодиться (оценить, когда дойдём)
- **Доступность:** управление с клавиатуры для всех кнопок, подписи для экранного диктора.
- **Тёмная тема интерфейса** (сам лист для печати остаётся светлым).
- **Слои-группы:** «сгруппировать» объекты, чтобы двигать их как одно целое между сессиями.
- **История версий макета:** несколько автоматических резервных копий в IndexedDB с датами («вчера»,
  «перед игрой»), откат к любой.
- **Языки интерфейса:** английский — если редактором захотят пользоваться другие игроки.
- **Мобильный телефон:** сейчас удобен ноутбук/планшет; для телефона нужен отдельный режим просмотра
  (связано с 5.1).
